# 图书借阅管理系统数据库说明

## 1. 数据库概述

本项目数据库用于支持高校图书馆图书借阅管理系统，主要完成图书信息、用户信息、角色权限、借阅记录等数据的存储与管理。

数据库采用 MySQL 8.0，数据库名为：

```sql
library
```

本项目实际开发时使用 MySQL 8.0 服务，连接端口为：

```text
3307
```

数据库设计重点包括：

- 使用主键唯一标识每条记录
- 使用外键维护表之间的引用完整性
- 使用唯一约束避免重复业务数据
- 使用非空约束保证核心字段完整
- 使用默认值减少重复初始化操作
- 使用 CHECK 约束限制状态字段和时间逻辑

## 2. SQL 文件说明

当前 SQL 目录包含以下文件：

| 文件名 | 作用 |
| --- | --- |
| `schema.sql` | 创建数据库表结构，包含主键、外键、唯一、非空、默认值、CHECK 等约束 |
| `seed.sql` | 插入初始测试数据，包括角色、权限、用户、作者、分类、图书和借阅记录 |
| `queries.sql` | 保存课程要求的查询 SQL，包括基础查询、多表连接查询、聚合查询和业务统计查询 |
| `test.sql` | 保存约束测试 SQL，用于验证重复数据、非法状态、非法外键等错误能否被数据库拦截 |
| `indexes.sql` | 保存必要的业务索引设计 |
| `explain.sql` | 保存典型查询的执行计划验证语句 |
| `auth_upgrade.sql` | 用于旧数据库升级，补充 `sys_user.password_hash` 字段 |

推荐执行顺序为：

```text
1. schema.sql
2. seed.sql
3. indexes.sql
4. queries.sql
5. explain.sql
6. test.sql
```

其中 `test.sql` 中的语句多为故意构造的非法数据测试，执行时报错属于正常现象，表示数据库约束已经生效。

## 3. 数据表设计

本数据库共设计 8 张核心表：

| 表名 | 中文含义 | 主要作用 |
| --- | --- | --- |
| `sys_role` | 角色表 | 保存普通读者、图书管理员、系统管理员等角色 |
| `sys_permission` | 权限表 | 保存系统中可执行操作的最小权限单元 |
| `sys_user` | 用户表 | 保存读者、图书管理员和系统管理员的账号信息，包含登录密码哈希 |
| `sys_role_permission` | 角色权限关联表 | 处理角色和权限之间的多对多关系 |
| `author` | 作者表 | 保存图书作者的基础信息 |
| `book_type` | 图书分类表 | 保存图书分类信息 |
| `book` | 图书表 | 保存馆藏图书信息 |
| `borrow_record` | 借阅记录表 | 保存用户借阅、归还图书的全过程记录 |

## 4. 表之间的关系

数据库中的主要外键关系如下：

| 从表字段 | 主表字段 | 关系说明 |
| --- | --- | --- |
| `sys_user.role_id` | `sys_role.role_id` | 一个用户属于一个角色 |
| `sys_role_permission.role_id` | `sys_role.role_id` | 一个角色可以关联多个权限 |
| `sys_role_permission.permission_id` | `sys_permission.permission_id` | 一个权限可以分配给多个角色 |
| `book.author_id` | `author.author_id` | 一本图书对应一个作者 |
| `book.type_id` | `book_type.type_id` | 一本图书对应一个分类 |
| `borrow_record.user_id` | `sys_user.user_id` | 一条借阅记录对应一个用户 |
| `borrow_record.book_id` | `book.book_id` | 一条借阅记录对应一本图书 |

其中，角色与权限之间是多对多关系，通过 `sys_role_permission` 中间表实现；用户与图书之间的借阅关系通过 `borrow_record` 记录。

## 5. 主要约束设计

### 5.1 主键约束

每张表均设置主键，用于唯一标识记录。例如：

- `sys_user.user_id`
- `book.book_id`
- `borrow_record.borrow_id`

### 5.2 外键约束

数据库通过外键约束维护引用完整性。例如：

- 用户必须关联一个已存在的角色
- 图书必须关联一个已存在的作者和分类
- 借阅记录必须关联已存在的用户和图书

外键删除策略使用 `RESTRICT`，当数据已经被其他表引用时，不允许直接删除，避免破坏历史记录。

### 5.3 唯一约束

为避免重复录入，以下字段设置唯一约束：

- `sys_user.user_no`：学号或工号唯一
- `sys_role.role_name`：角色名称唯一
- `sys_permission.permission_name`：权限名称唯一
- `sys_permission.permission_code`：权限标识唯一
- `sys_role_permission(role_id, permission_id)`：同一角色不能重复分配同一权限
- `book.isbn`：ISBN 唯一
- `book_type.type_name`：分类名称唯一

### 5.4 CHECK 约束

本项目使用 MySQL 8.0，能够正常支持 CHECK 约束。

状态字段约束如下：

| 字段 | 合法值 | 含义 |
| --- | --- | --- |
| `sys_user.account_status` | `0, 1` | 0 表示禁用，1 表示正常 |
| `book.book_status` | `0, 1, 2` | 0 表示在馆可借，1 表示借出中，2 表示停用或下架 |
| `borrow_record.borrow_status` | `0, 1, 2` | 0 表示未归还，1 表示已归还，2 表示逾期 |

借阅记录还设置了时间逻辑约束：

- `due_return_time` 必须晚于 `borrow_time`
- 当 `borrow_status` 为未归还或逾期时，`actual_return_time` 必须为空
- 当 `borrow_status` 为已归还时，`actual_return_time` 不能为空，且不能早于 `borrow_time`

### 5.5 默认值约束

部分字段设置默认值：

- `sys_role.create_time` 默认当前时间
- `sys_user.register_time` 默认当前时间
- `sys_user.account_status` 默认正常
- `book.book_status` 默认在馆可借
- `borrow_record.borrow_time` 默认当前时间
- `borrow_record.borrow_status` 默认未归还

## 6. 初始数据设计

`seed.sql` 中包含用于系统演示和测试的初始数据，主要包括：

- 3 个角色：普通读者、图书管理员、系统管理员
- 多个权限：图书查询、图书管理、借阅图书、归还图书、用户管理、统计查询等
- 多条角色权限关联数据
- 多个系统用户
- 初始用户默认演示密码为 `123456`，数据库保存的是 SHA-256 哈希值，不保存明文密码
- 多个作者
- 多个图书分类
- 多本图书
- 多条借阅记录

这些数据可以支持后续前后端功能演示，例如图书查询、借阅记录查询、逾期记录查询和分类统计。

## 7. 查询设计

`queries.sql` 中包含课程要求的查询类型：

- 基础查询：例如查询可借图书、按书名查询图书、查询正常状态用户
- 多表连接查询：例如查询图书详细信息、查询用户借阅历史
- 聚合查询：例如统计每个分类下的图书数量
- 业务统计查询：例如查询逾期未还记录、统计借阅次数最多的图书分类

这些查询能够体现数据库表结构对实际业务场景的支持。

## 8. 约束测试说明

`test.sql` 用于验证数据库约束是否实际生效，测试内容包括：

- 插入重复学号或工号，预期失败
- 插入非法账号状态，预期失败
- 插入不存在的角色 ID，预期失败
- 重复分配角色权限，预期失败
- 设置非法图书状态，预期失败
- 设置非法借阅状态，预期失败
- 插入不合理的借阅时间，预期失败
- 删除已经被引用的角色或图书，预期失败

如果执行这些测试 SQL 时 MySQL 报错，说明对应约束正常生效。

## 9. 后续系统实现说明

  datasource:
    url: jdbc:mysql://localhost:3307/library?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai

## 10. 性能优化设计

### 10.1 索引设计

项目新增 `indexes.sql`，用于为高频查询建立索引。索引设计重点放在借阅历史查询、逾期查询、图书分类统计和 Agent 审计时间线查询上。经过选择性分析，`book_status`、`role_id`、`account_status` 等低选择性字段不再单独作为组合索引最左列。

主要索引包括：

- `idx_book_type_status`：服务于图书分类统计和按分类、状态筛选的查询。
- `idx_borrow_status_due_time`：服务于逾期未还记录查询。
- `idx_borrow_user_time`：服务于某个用户的借阅历史查询，覆盖 `WHERE user_id = ? ORDER BY borrow_time DESC, borrow_id DESC` 场景。
- `idx_borrow_user_status_time`：服务于某个用户按借阅状态筛选历史记录的查询，覆盖 `WHERE user_id = ? AND borrow_status = ? ORDER BY borrow_time DESC, borrow_id DESC` 场景。
- `idx_agent_log_user_time`：服务于 Agent 操作审计中按用户查看操作时间线的查询。

登录接口使用 `sys_user.user_no` 查询账号，该字段已经通过 `UNIQUE` 约束自动建立唯一索引，因此不再重复创建单独索引。

MySQL InnoDB 在创建外键时通常会为外键列建立可用索引，因此本项目没有简单重复为所有外键字段建立单列索引，而是结合业务查询增加组合索引。

### 10.2 EXPLAIN 查询计划验证

项目新增 `explain.sql`，用于查看典型 SQL 的执行计划。通过 `EXPLAIN` 可以观察 MySQL 是否使用了预期索引，例如：

- 图书列表查询是否利用图书状态索引。
- 用户列表查询是否利用角色和账号状态组合索引。
- 用户借阅历史查询是否利用 `user_id + borrow_time` 索引。
- 用户按状态筛选借阅历史时是否利用 `user_id + borrow_status + borrow_time` 索引。
- 逾期未还查询是否利用 `borrow_status + due_return_time` 索引。
- 分类统计查询是否利用图书分类相关索引。

在课程项目当前数据量较小时，索引带来的性能差异不明显，但从系统扩展角度看，图书、用户和借阅记录数量增长后，索引可以减少全表扫描，提高查询稳定性。

### 10.3 分页查询

后端已为以下列表接口增加分页参数：

- `GET /api/books?page=1&pageSize=10`
- `GET /api/users?page=1&pageSize=10`
- `GET /api/borrows?page=1&pageSize=10`

分页查询通过 `LIMIT offset, pageSize` 实现，避免数据量较大时一次性返回全部记录，减少数据库扫描量、网络传输量和前端渲染压力。

为了兼容已有前端调用，上述接口在不传 `page` 或 `pageSize` 时仍返回原来的数组结构；传入分页参数时返回分页对象：

```json
{
  "page": 1,
  "pageSize": 10,
  "total": 20,
  "records": []
}
```

### 10.4 基础数据缓存

作者、图书分类、角色等基础数据变化频率较低。前端在页面初始化时统一请求：

- `/api/authors`
- `/api/book-types`
- `/api/roles`

这些数据加载后保存在前端状态中，页面切换时不重复请求，从而减少不必要的接口访问和数据库查询。

### 10.5 借阅记录归档

`borrow_record` 是系统中增长最快的业务事实表。随着系统长期运行，历史借阅记录会持续增加，影响当前借阅查询、逾期查询和统计查询的效率。

项目新增 `archive_design.sql` 作为扩展设计，提供 `borrow_record_archive` 历史归档表。后续可将已经归还且时间较久的记录迁移到归档表中：

- `borrow_record` 保留当前和近期业务记录。
- `borrow_record_archive` 保存历史借阅记录。

这样可以减少日常业务查询扫描的数据范围，同时保留历史数据用于追溯和统计。
